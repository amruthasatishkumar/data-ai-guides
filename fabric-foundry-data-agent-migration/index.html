Microsoft Fabric + Microsoft Foundry

The Fabric data agent tool in Foundry is retiring. Here is what to use instead.

If your Foundry agents call a Fabric data agent through the Microsoft Fabric data agent tool (the connection set up with a workspace ID and artifact ID), you need to move to a supported path. Your Fabric data agents and their data don't change; only the way Foundry connects to them does.

Nov 6, 2026
Microsoft's documentation states the Microsoft Fabric data agent tool in Foundry Agent Service is no longer supported starting November 6, 2026, and directs customers to the Fabric IQ tool.

What's going away

Only one integration is retiring: the Microsoft Fabric data agent tool inside Microsoft Foundry Agent Service. Your Fabric data agents themselves are not retiring.

The retiring integration

Your Fabric data agentAnswers using data the signed-in user can access

Microsoft's documentation states this integration won't be supported starting November 6, 2026, and that Foundry agents using it must be migrated.

Who is affected

  • Teams with Foundry agents that call a Fabric data agent through the Microsoft Fabric tool or knowledge source.
  • Applications, bots and copilots built on top of those Foundry agents.
  • Code that creates agents with the Fabric data agent tool, for example FabricTool, MicrosoftFabricPreviewTool or the fabric_dataagent_preview tool type.
  • Automation that creates the Fabric project connection with workspace_id and artifact_id keys.

What it means for you

  • Microsoft no longer supports the integration from November 6, 2026. Treat any agent still using it as at risk of failing to answer data questions.
  • Don't count on support or fixes for issues with this tool.
  • New agents should not be built on it.
  • Plan to update, test and redeploy each affected agent.

How to check if you're using it

  1. In the Foundry portal, open each agent and look under Tools or Knowledge for Microsoft Fabric or Microsoft Fabric data agent.
  2. In your Foundry project's connections, look for Fabric connections that store a workspace ID and an artifact ID.
  3. Search your code and pipelines for FabricTool, MicrosoftFabricPreviewTool, FabricDataAgentToolParameters or fabric_dataagent_preview.

What isn't changing

  • Your published Fabric data agents, their instructions and their data sources.
  • Fabric permissions: users still only get answers from data they can access.
  • Fabric capacity requirements: paid F2 or higher, or Power BI Premium P1 or higher with Fabric enabled.
  • The data in OneLake. Nothing needs to be moved or copied.
Next step: if you found any affected agents, see Your options for the supported ways to keep those agents connected to your Fabric data agents, then How to migrate.

Your options

For Fabric data agents, both alternatives call the same thing: the MCP endpoint that every published data agent exposes. The difference is who calls it and how it's managed. Inside Foundry, Microsoft documents Alternative 1 as the migration path. Alternative 2 is for clients outside Foundry, or when you need a service principal.

Microsoft's documented replacement
Alternative 1

Fabric IQ (OneLake Catalog) tool in Foundry PREVIEW

Microsoft's documented replacement. Add the tool to your Foundry agent, pick published data agents from the OneLake Catalog, and Foundry manages the connection.

  • Best for: agents built in Microsoft Foundry (portal, prompt agents, hosted agents).
  • Connects to: Fabric data agents, plus ontologies and Power BI semantic models.
  • Identity: delegated user access (signed-in user), or a separate OAuth session through a managed or custom OAuth app.
  • SDKs: Python, C#, JavaScript, REST. No Java.
  • Extras: several data agents per agent, background mode, reusable through a Foundry toolbox.
Alternative 2

Call the data agent's MCP endpoint directly

Every published data agent is an MCP server with one tool. Any MCP client that supports streamable HTTP and can attach a Fabric bearer token can call it.

  • Best for: custom apps, services and jobs, other agent frameworks, VS Code, or anything outside Foundry.
  • Endpoint: https://api.fabric.microsoft.com/v1/mcp/workspaces/{workspaceId}/dataagents/{dataAgentId}/agent
  • Identity: a user or a service principal token for scope https://api.fabric.microsoft.com/.default.
  • Long-running: supports the MCP tasks extension (tasks/get, tasks/cancel).
  • You own: token acquisition, orchestration, retries and error handling.

Don't confuse these with the "Fabric IQ MCP server"

There is also a general-purpose Fabric IQ MCP server (fabriciq.svc.cloud.microsoft/v1/mcp/fabriciq, generally available) for querying Power BI reports and semantic models from MCP clients such as GitHub Copilot CLI. It is read-only, uses delegated user sign-in only, and doesn't currently support Fabric data agents or ontologies. It is not a replacement for the retiring tool, but it can be the right fit if your goal is Q&A over Power BI semantic models outside Foundry.

How to migrate

Your published data agent doesn't change. Only the Foundry tool (or your client) changes.

  1. Confirm the Fabric data agent is published and answers correctly in Fabric. Only published agents appear in the catalog.
  2. Open your agent in the Foundry portal. Under Tools, select Add > Browse all tools > Fabric IQ (OneLake Catalog), then Add tool.
  3. In the OneLake Catalog, filter Type to Data agent, select your data agent, and select Add. Repeat for each data agent you need.
  4. Update the agent's instructions: name each data agent and the questions it should handle (for example, "Use the Contoso Sales data agent for revenue and orders").
  5. Remove the old Microsoft Fabric data agent tool and select Save. Changes aren't kept until you save.
  6. Test in the playground with representative questions for each data agent, and with a user who lacks access to confirm permissions are enforced.
  7. For slow queries, pick a model that supports background mode (such as gpt-5.4 or gpt-5.5) and turn it on in the model parameters.
  1. Get the data agent MCP endpoint: https://api.fabric.microsoft.com/v1/mcp/workspaces/{workspaceId}/dataagents/{dataAgentId}/agent (IDs are in the data agent's browser URL).
  2. Create a Fabric IQ project connection in the Foundry portal (requires the Foundry Project Manager role).
  3. In your agent definition, replace the old fabric_dataagent_preview tool with the Fabric IQ tool, passing project_connection_id, server_url and a short server_label. Use azure-ai-projects>=2.2.0 for Python.
  4. For hosted agents, add the Fabric IQ tool to a toolbox and connect the agent to the toolbox MCP endpoint.
  5. Update instructions, remove the old tool configuration, and test before switching your application.

Code samples for each language are in "Connect agents to Microsoft Fabric with Fabric IQ" on Microsoft Learn. The Java SDK doesn't support Fabric IQ.

  1. Publish the data agent, then open Settings > Model Context Protocol to copy the MCP server URL and tool description (or download mcp.json).
  2. Write a clear, specific data agent description. It becomes the MCP tool description that clients use to decide when to call it.
  3. Acquire a Fabric token for scope https://api.fabric.microsoft.com/.default as a user or a service principal, and attach it as a bearer token on every request.
  4. Use an MCP client or SDK: initialize, then tools/list, then tools/call with the question. A plain REST call won't work.
  5. Handle long-running questions with the MCP tasks extension if your client supports it.

What to be mindful of

From Microsoft's documentation for the Fabric IQ tool and the data agent MCP server.

It's a preview

The Fabric IQ tool in Foundry is in preview, without an SLA. Plan testing and change control accordingly.

Data can leave Fabric's boundary

Responses returned by data agents can be sent outside Fabric's compliance boundary or region and handled under Foundry's or your MCP client's terms. Review with privacy and compliance.

Region support

Fabric IQ isn't available in regions where Power BI is the only Fabric workload. Keep the data agent and its data sources on capacities in the same region.

Cross-region results

If the Foundry project and the Fabric workspace are in different Azure regions, query results are returned cross-region.

Licensing and capacity

Data agents need paid F2+ or Premium P1+ capacity. Users who invoke Fabric IQ through your agent need a Fabric license for the items they query.

Same tenant, same account

The data agent and Foundry must be in the same tenant; sign in to both with the same account when using the portal.

Write good instructions

Name each data agent and the questions it covers. Without this, the agent may not call a data agent or may call the wrong one.

Descriptions drive routing

For direct MCP use, the published data agent description is the tool description clients rely on. Make it specific.

Long-running queries

Use background mode in Foundry (gpt-5.4, gpt-5.5) or the MCP tasks extension for direct clients.

Identity choices

Foundry connections use delegated user access. Service principal tokens work only when calling the data agent MCP endpoint directly.

Admin consent for custom OAuth apps

A bring-your-own Entra app for data agents needs DataAgent.Execute.All with admin consent (Power BI Item.Read.All / Item.Execute.All for ontology).

Networking and SDKs

Semantic model endpoints are public only. Workspace-level private link needs a workspace-specific host. No Java SDK support for Fabric IQ.

Costs

Microsoft notes that connecting to Fabric IQ may incur costs. This typically includes model usage in Foundry and Fabric capacity consumption when data agents run queries.

Renamed Foundry roles

Foundry User, Foundry Owner, Foundry Account Owner and Foundry Project Manager were previously Azure AI User, Azure AI Owner, Azure AI Account Owner and Azure AI Project Manager. Role IDs didn't change.

FAQ

Do I need to rebuild my Fabric data agents?
No. Microsoft states the migration changes the Foundry tool integration, not the Fabric data agent or its data sources. Keep using your published data agents.
Will answers be different after migrating?
The Fabric data agent still produces the answer, and the model you choose in Foundry is only used for orchestration and replies. Results can differ if your agent now routes between several data agents, so test with representative questions.
Can one Foundry agent use several data agents now?
Yes. With the Fabric IQ (OneLake Catalog) tool you add data agents one at a time, and each appears as its own tool. The retiring tool allowed only one.
Can I run it without a signed-in user?
Only by calling the data agent MCP endpoint directly with a service principal token. Foundry connections for data agents use delegated user access.
Is the "Fabric IQ MCP server" the same as the Fabric IQ tool in Foundry?
No. The Fabric IQ tool in Foundry calls item-specific endpoints (data agent, ontology, semantic model). The general Fabric IQ MCP server is a separate, read-only server for Power BI reports and semantic models that doesn't currently support data agents or ontologies.
What happens if I don't migrate?
Microsoft's documentation says the retiring integration isn't supported starting November 6, 2026, and that agents using it must migrate. Treat any agent still using it as at risk of failing.
Does this affect other ways of using Fabric data agents?
The retirement notice covers the Microsoft Fabric data agent tool in Foundry Agent Service. Using data agents in Fabric itself, or through other integrations, isn't part of this notice. Check the documentation for each integration you use.
Do I need new permissions to migrate?
Users still need read access to the data agent and each underlying data source. In Foundry, people who build and test agents need Foundry User, and whoever creates the Fabric IQ connection needs Foundry Project Manager. If you use your own Entra app for the connection, a Global Administrator must grant admin consent once.
