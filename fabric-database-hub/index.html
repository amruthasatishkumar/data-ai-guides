Understand Fabric Database Hub and Fabric databases in minutes.

A practical map of Database Hub (preview), the estate-wide operations experience in Microsoft Fabric, and of the database items you create in Fabric workspaces: what each one is, how to reach it, and why permissions change what each person sees.

Start here

Database Hub watches your databases. It is not a database.

Database Hub (preview) gives database teams one place to discover, prioritize, monitor, and investigate supported databases across Azure, Fabric, on-premises (through Azure Arc), and supported multicloud environments. The databases themselves stay where they are: in Fabric workspaces or in Azure subscriptions.

!
Key facts to know Database Hub is its own preview experience, not just another name for the Fabric Databases landing page:
  • Database Hub (preview) is an estate-wide operations view with Overview, Estate, and Performance pages. A Fabric Free license is enough to open it; no Fabric capacity is required.
  • It covers Azure and Arc-enabled databases, not only Fabric items, and it uses your existing Microsoft Entra ID, Azure RBAC, and Fabric permissions.
  • In the current preview it does not support Cosmos DB in Fabric, mirrored databases in Fabric, or Fabric Data Warehouse.
  • SQL database in Fabric and Cosmos DB in Fabric are generally available (announced November 2025). Several mirroring sources changed status in 2026.

Workspaces and subscriptions

Fabric databases belong to capacity-backed Fabric workspaces. Azure databases stay in their Azure subscriptions. Nothing moves into Fabric just to be monitored.

Database item + native tools

Open the database to query, build, share, connect external tools, or analyze its OneLake copy. Deeper diagnostics stay in each engine's native tools.

Visibility and permissions

You only see what you can reach.

Database Hub and Fabric search are permission-trimmed. A missing database is usually an access, workspace, Azure RBAC, region, or preview-enrollment issue, not a catalog failure.

1. Sign-in and license

Sign in with Microsoft Entra ID, and your organization must allow Fabric. A Fabric Free license is enough for Database Hub; Fabric database items need a capacity-backed workspace.

2. Two separate control planes

Fabric workspace roles and item sharing control Fabric databases. Azure RBAC controls Azure databases; Database Hub discovers them through Azure Resource Graph. Fabric roles do not grant Azure access, and the reverse is also true.

3. Data-plane permission

Seeing an item or resource does not grant every data permission. Fabric item Read alone does not give access to data in SQL or OneLake, and Azure Cosmos DB data needs its own data-plane role.

AdminCreate, modify, share, manage
MemberCreate, modify, share
ContributorCreate and modify
ViewerView; no item creation

The workspace role matrix says Contributors can create or modify database and database mirroring items. The SQL database create tutorial and the Azure SQL Database mirroring tutorial both list workspace Admin or Member as prerequisites, and sharing a mirrored database requires Admin or Member. Follow the item-specific prerequisite when they differ. For Database Hub performance monitoring, you need at least the Azure Reader role on each subscription you want to monitor. Sharing a Database Hub view shares its filters, not access.

Fast diagnosis

When the page does not look as expected

I cannot find Database Hub.
Database Hub is in preview. What appears depends on tenant configuration, region, permissions, and preview enrollment, and your organization must allow access to Fabric and Database Hub. Microsoft Learn documents entry points from the Fabric navigation, from Power BI or Fabric web experiences, from supported Azure database experiences, and from a direct link: https://powerbi.com/workloads/fdh/databaseHub. Also check Fabric region availability.
My Azure databases do not appear in Database Hub.
Sign in with the same Microsoft Entra account and directory you use in the Azure portal, and confirm you can see the resources there. Ask your Azure administrator for read access (for example, Reader) at an approved scope. For Microsoft SQL resources, register the Microsoft.Sql resource provider in each subscription; for Azure SQL Database performance data, select Enable Performance Monitoring on the Estate page or add the documented extended property. Sign out and back in after access changes, and allow time for new telemetry to arrive.
A Fabric database is missing from Database Hub.
In the current preview, Cosmos DB in Fabric, mirrored databases, and Fabric Data Warehouse are not supported in Database Hub. SQL database in Fabric appears on the Estate page but not yet on the Performance page. Fabric permissions are managed separately from Azure permissions, so check your workspace role or item sharing.
A colleague sees different resources in a view I shared.
This is expected. A shared view keeps its scope and filters, but each person sees only the resources their own Azure or Fabric permissions allow.
I can see a database, but cannot query its data.
Fabric item Read lets you see metadata; it does not guarantee SQL or OneLake data access. Check database permissions, SQL analytics endpoint permissions, and OneLake security separately. For an Azure Cosmos DB account that appears in Estate, you also need a Cosmos DB data-plane role assignment and network access.
I cannot create a SQL database or Cosmos DB database.
Verify that a Fabric capacity (or trial) backs the target workspace and that you meet the item-specific workspace role prerequisite. For Cosmos DB, if the tile is not shown, select See all in the Create pane and look in the Databases category. Also check tenant controls and regional availability.
My mirrored database is not current.
Check source connectivity, replication status, capacity state, gateway health, and source-side prerequisites. Near real-time replication depends on source and destination region, the volume and frequency of changes, network bandwidth and latency, and gateway compute resources.
